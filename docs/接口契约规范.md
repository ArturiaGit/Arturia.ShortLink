## 1. 全局约定与协议规范

### 1.1 基础请求头 (Headers)
* `Content-Type: application/json; charset=utf-8`
* `Authorization: Bearer <jwt_token_or_api_key>`（管理端业务接口必传；登录、注册、健康检查、公网跳转与密码解锁除外）
* `X-Workspace-Id: <workspace_id>`（JWT 管理端请求的租户上下文；API Key 请求必须与密钥所属空间一致）
* API Key 的固定授权面仅包含短链列表、别名检查、创建、更新、启停与删除；认证、工作空间/成员、域名、API Key 管理及管理员封禁端点只接受 JWT。API Key 调用超出固定授权面的接口返回 HTTP 403。

### 1.2 JSON、ID 与时间

* JSON 属性统一使用 `camelCase`。
* 数据库主键使用 `BIGINT UNSIGNED`；HTTP 请求路径、Query 与 DTO 中的所有 ID 均为十进制字符串。
* 时间统一按 UTC 计算和存储，以 ISO 8601 字符串返回；禁止返回依赖宿主本地时区的时间。
* 域名 SSL 状态固定为 `Active | Pending | Error`；空间角色固定为 `owner | admin | member`。

### 1.3 统一响应结构 (Response Envelope)

所有接口统一以 JSON 格式返回如下结构：

```typescript
interface ApiResponse<T = any> {
  code: number;      // 业务状态码：200 表示成功，非 200 表示业务异常
  success: boolean;  // 业务是否处理成功
  message: string;   // 提示信息（如 "操作成功"、"短码已被占用"）
  data: T | null;    // 成功时为数据负载；失败时通常为 null
}
```

成功响应使用 HTTP 200/201/202，并始终返回统一响应体；为兼容当前前端拦截器，成功响应体的 `code` 固定为 `200`。失败使用真实 HTTP 400/401/403/404/409/422/429/500，错误体仍使用 `ApiResponse<null>`，且 `code` 与 HTTP 状态码一致。Mock 与真实后端不得把业务错误统一伪装为 HTTP 200，未知端点必须返回 404。

### 1.4 分页统一响应结构 (Page Result)

```typescript
interface PageResult<T> {
  items: T[];
  total: number;
  page: number;
  pageSize: number;
  totalPages: number;
}
```

### 1.5 状态码与验证错误

| HTTP 状态 | 使用场景 |
| :---: | :--- |
| `400` | JSON/Query 格式错误、缺少必填参数 |
| `401` | 登录凭据错误、JWT/API Key 缺失或无效 |
| `403` | 已认证但 RBAC、租户或资源归属校验失败 |
| `404` | 资源或路由不存在 |
| `409` | 唯一键、成员、邀请、域名或 Slug 冲突 |
| `422` | 请求格式合法但业务规则不接受，例如危险 URL、自环或过去的到期时间 |
| `429` | 触发限流 |
| `500` | 未知服务端异常；不得向客户端泄露堆栈、连接串或凭据 |

字段验证失败时，`data` 可返回 `{ "errors": { "fieldName": ["中文错误说明"] } }`；其他业务失败的 `data` 为 `null`。

登录/注册 Token、API Key 一次性明文与密码解锁票据响应必须发送 `Cache-Control: no-store`，且不得被结构化请求/响应日志记录。

### 1.6 默认限流契约

* 登录与密码解锁：每 IP 每分钟 10 次。
* 短链创建：每用户或 API Key 每分钟 30 次。
* 公网跳转：每 IP 每分钟 120 次。
* 触发限流统一返回 HTTP 429 与 `ApiResponse`；真实后端不得接受 Mock 专用旁路参数。

## 2. 认证与用户模块 (Auth & User)

### 2.1 用户登录
* **路径**: `POST /api/v1/auth/login`
* **请求体**:
```json
{
  "email": "admin@arturia.link",
  "password": "password123!"
}
```
* **响应 `data`**:
```json
{
  "token": "eyJhbGciOi...",
  "user": {
    "id": "1",
    "email": "admin@arturia.link",
    "nickname": "Arturia Admin",
    "avatarUrl": "https://images.unsplash.com/..."
  },
  "workspaces": [
    { "id": "1", "name": "Arturia 官方团队", "slug": "arturia-core", "role": "owner" }
  ]
}
```

### 2.2 用户注册
* **路径**: `POST /api/v1/auth/register`
* **请求体**:
```json
{
  "email": "user@example.com",
  "password": "Password123!",
  "nickname": "张三"
}
```

* **响应 `data`**: 与登录成功响应一致，包含 `token`、不含密码字段的 `user` 和已创建/已加入的 `workspaces`。
* **双重并存初始化与邀请消费**:
  * **强制个人空间**：用户注册时，系统强制为其初始化独立的个人工作空间（授予 `owner` 角色），空间名称默认 `"{nickname}的工作空间"`；
  * **初始 Slug 规范化生成**：由系统按「邮箱前缀规范化 + 4位防重随机码」自动生成（如 `user-a7x9`），去除非小写字母和数字字符，保证全局唯一并严格符合 `^[a-z0-9](?:[a-z0-9-]{1,30}[a-z0-9])?$`；
  * **主域名绑定**：在同一事务中为该空间绑定系统域名 `art.link` 设为主域名；
  * **原子接受全部有效邀请**：在同一事务中同时查询该注册邮箱的有效待处理邀请，全部接受加入对应工作空间（创建成员关系并将邀请状态置为 `accepted`）。已超过 `expiresAt` 的 `pending` 邀请自动转为 `expired`，不得继续阻挡同工作空间重新邀请。

### 2.3 获取当前登录人信息
* **路径**: `GET /api/v1/auth/me`
* **响应 `data`**: `{ "user": UserDto, "workspaces": WorkspaceDto[] }`；任何响应均不得包含 `password` 或 `passwordHash`。

## 3. 工作空间与团队模块 (Workspace & Team)

### 3.1 获取当前用户的所有工作空间
* **路径**: `GET /api/v1/workspaces`

### 3.2 创建新工作空间
* **路径**: `POST /api/v1/workspaces`
* **请求体**:
```json
{
  "name": "海外增长团队",
  "slug": "global-growth"
}
```

* **Slug 规则**: 规范化为小写，格式固定为 `^[a-z0-9](?:[a-z0-9-]{1,30}[a-z0-9])?$`（3～32 位，不允许连续语义外的空白、中文、下划线或首尾短横线）；全局冲突返回 HTTP 409。
* **原子初始化规则**: 创建空间、写入当前用户的 `owner` 成员关系、绑定全局系统域名 `art.link` 并将其设为该空间主域名必须在同一事务中完成；响应为新建 `WorkspaceDto`。

### 3.3 检查工作空间 Slug
* **路径**: `GET /api/v1/workspaces/check-slug?slug={slug}`
* **响应 `data`**: `{ "available": true, "message": "该标识可用" }`
* **规则**: 使用与创建接口完全相同的规范化和格式校验；格式非法返回 HTTP 400，不得以 `available=true` 掩盖。

### 3.4 获取工作空间成员列表
* **路径**: `GET /api/v1/workspaces/{workspaceId}/members`
* **租户规则**: `{workspaceId}` 必须与解析后的当前工作空间一致，否则返回 HTTP 403。
* **响应 `data`**:
```json
[
  {
    "id": "1",
    "userId": "1",
    "email": "admin@arturia.link",
    "nickname": "Arturia Admin",
    "avatarUrl": "https://images.unsplash.com/...",
    "role": "owner",
    "joinedAt": "2026-09-01T10:00:00Z"
  }
]
```

### 3.5 邀请成员加入工作空间
* **路径**: `POST /api/v1/workspaces/{workspaceId}/members`
* **请求体**:
```json
{
  "email": "colleague@company.com",
  "role": "member" // "admin" | "member"
}
```

* 已注册账号立即创建成员关系并返回 `TeamMemberDto`。
* 未注册邮箱创建 7 天有效的一次性邀请并返回 HTTP 202；同邮箱注册后自动接受邀请。
* 同工作空间已存在成员或待处理邀请时返回 HTTP 409。

### 3.6 修改成员角色
* **路径**: `PUT /api/v1/workspaces/{workspaceId}/members/{memberId}`
* **请求体**: `{ "role": "admin" }`
* **规则**: Owner 可在 `admin/member` 间调整；Admin 仅可管理 Member；不得通过此接口转让或降级 Owner。

### 3.7 移除成员
* **路径**: `DELETE /api/v1/workspaces/{workspaceId}/members/{memberId}`
* **规则**: 路径末段是成员关系 ID，不是用户 ID；Owner 不得自删，Admin 只能移除 Member。

## 4. 自定义域名模块 (Domains)

### 4.1 获取当前工作空间的域名列表
* **路径**: `GET /api/v1/domains`
* **ID 语义**: `DomainDto.id` 与后续 `{domainId}` 均表示全局 `link_domain.id`；服务端执行任何操作前仍必须通过当前租户的 `workspace_domain` 绑定校验授权，绑定表自身主键不暴露给前端。
* **响应 `data`**:
```json
[
  {
    "id": "1",
    "domain": "art.link",
    "isPrimary": true,
    "isSystem": true,
    "isVerified": true,
    "sslStatus": "Active",
    "cnameTarget": "cname.art.link",
    "linkCount": 3,
    "createdAt": "2026-09-01T08:00:00Z"
  },
  {
    "id": "2",
    "domain": "go.arturia.dev",
    "isPrimary": false,
    "isSystem": false,
    "isVerified": true,
    "verificationCode": "cname-arturia-98124",
    "sslStatus": "Active",
    "cnameTarget": "cname.art.link",
    "linkCount": 1,
    "createdAt": "2026-09-02T14:30:00Z"
  }
]
```

### 4.2 添加自定义域名
* **路径**: `POST /api/v1/domains`
* **请求体**:
```json
{
  "domain": "link.mybrand.com"
}
```

* 域名在写入前规范化为小写 Host，不允许协议、端口、路径或通配符。
* 同一自定义域名全平台只能归属一个工作空间；冲突返回 HTTP 409。

### 4.3 触发 DNS CNAME 校验
* **路径**: `POST /api/v1/domains/{domainId}/verify`
* **响应说明**: 后端查询 DNS 记录，成功则将 `isVerified` 置为 `true`，并按当前网关启用结果返回 `sslStatus: "Active"`；DNS/网关失败返回可诊断业务错误，不得抛出未处理 500。
* **Mock 专用参数**: 当前前端 Mock 可使用 `simulateFail=true` 演示失败态；该参数不得进入真实后端路由、OpenAPI 或生产实现。

### 4.4 删除域名
* **路径**: `DELETE /api/v1/domains/{domainId}`
* **规则**: 禁止删除系统域名；只要该绑定存在任意短链记录（包括已软删除的历史归档）即返回 HTTP 409。仅从未关联短链的自定义域名可在事务中删除租户绑定及无引用的全局注册记录。

### 4.5 获取域名统计
* **路径**: `GET /api/v1/domains/stats`
* **响应 `data`**:
```json
{
  "total": 2,
  "activeCount": 2,
  "pendingCount": 0,
  "primaryDomain": "art.link",
  "maxDomains": 11
}
```

`total` 包含系统域名与自定义域名；数据库 `sys_workspace.max_domains` 表示自定义域名配额，因此供当前前端展示的 `maxDomains` 等于“自定义域名配额 + 当前系统域名绑定数”，避免系统域名占用租户购买的自定义域名额度。

### 4.6 设置主域名
* **路径**: `POST /api/v1/domains/{domainId}/primary`
* **规则**: 目标必须已绑定当前工作空间且已验证；事务内原子清除旧主域名并设置新主域名。
* **响应 `data`**: 更新后的 `DomainDto`。

## 5. 短链核心模块 (Links)

### 5.1 分页查询短链列表
* **路径**: `GET /api/v1/links`
* **Query 参数**:
  * `page`: 当前页码（从 1 开始，默认 1）
  * `pageSize`: 每页条数（默认 50，最大 100；当前分析页会显式请求 100）
  * `search`: 关键词搜索（匹配别名 slug / 标题 / 原始 URL）
  * `domain`: 域名 Host 过滤（可选）
  * `isEnabled`: 启用状态过滤（可选，true / false）
* **响应 `data`**: `PageResult<ShortLinkItem>`
```json
{
  "items": [
    {
      "id": "1",
      "workspaceId": "1",
      "domain": "art.link",
      "slug": "github-repo",
      "fullShortUrl": "https://art.link/github-repo",
      "originalUrl": "https://github.com/dotnet/aspnetcore",
      "title": "ASP.NET Core 官方主页",
      "description": "微软官方开源高性能 Web 框架仓库",
      "isEnabled": true,
      "isBanned": false,
      "hasPassword": false,
      "expiresAt": null,
      "pvCount": 3482,
      "uvCount": 2190,
      "createdById": "1",
      "creatorName": "Arturia Admin",
      "creatorAvatar": "https://images.unsplash.com/...",
      "createdAt": "2026-09-01T12:00:00Z"
    }
  ],
  "total": 1,
  "page": 1,
  "pageSize": 50,
  "totalPages": 1
}
```

### 5.2 创建短链
* **路径**: `POST /api/v1/links`
* **说明**: 服务端从请求头 `Authorization` 解析有效主体。JWT 请求将 `created_by` 绑定为当前用户 ID；API Key 请求将其绑定为该密钥不可变的 `createdBy` 用户 ID，禁止由请求体指定或伪造创建者。
* **请求体**:
```json
{
  "originalUrl": "https://dotnet.microsoft.com/download/dotnet/10.0",
  "domain": "art.link",
  "slug": "dotnet10",             // 可选；若未提供则系统自动生成 6 位 Base62 字符
  "title": ".NET 10 正式版下载",   // 可选；链接别称
  "description": "最新运行时下载页面",
  "password": "",                 // 可选；访问保护密码
  "expiresAt": null,              // 可选；ISO 8601 时间戳
}
```

* 前端 UTM 构建器将参数写入 `originalUrl` 查询串；后端解析五项标准 UTM 字段用于持久化，但 DTO 返回保持用户提交的完整 URL。
* `domain` 必须是当前工作空间已绑定且可用的域名；不存在或未授权返回 HTTP 422/403。
* 响应不得包含 `password` 或 `passwordHash`，仅通过 `hasPassword` 表示保护状态。

### 5.3 检查短链别名
* **路径**: `GET /api/v1/links/check-slug`
* **Query 参数**: `domain`、`slug`、可选 `excludeId`（待排除的短链 `short_link.id`，用于编辑态检查）。
* **响应 `data`**: `{ "available": false, "message": "该别名已被占用" }`

### 5.4 更新短链
* **路径**: `PUT /api/v1/links/{id}`
* **权限规则 (RBAC)**：空间 `owner` 与 `admin` 可修改空间内全部短链；`member` 仅可修改本人创建的短链，越权操作返回 403 Forbidden (`{ "code": 403, "success": false, "message": "无权限：业务协作者仅可修改本人创建的短链" }`)。
* **请求体**:
```json
{
  "originalUrl": "https://dotnet.microsoft.com/download/dotnet/10.0",
  "title": ".NET 10 正式版下载",
  "description": "最新运行时下载页面",
  "hasPassword": true,
  "password": "new-password",
  "expiresAt": null
}
```
* **字段语义**: 当前已验收前端不通过此接口修改 `domain` 或 `slug`；`hasPassword=false` 明确移除密码，`hasPassword=true` 且提供非空 `password` 时设置/替换密码，`hasPassword=true` 且省略 `password` 时保留原密码。响应不得返回密码明文或哈希。

### 5.5 快速切换短链启停状态
* **路径**: `PATCH /api/v1/links/{id}/status`
* **权限规则 (RBAC)**：空间 `owner` 与 `admin` 可启停全部短链；`member` 仅可启停本人创建的短链，越权操作返回 403 Forbidden。
* **请求体**: 无。服务端原子翻转 `isEnabled` 并返回更新后的 `ShortLinkDto`。

### 5.6 删除短链
* **路径**: `DELETE /api/v1/links/{id}`
* **权限规则 (RBAC)**：空间 `owner` 与 `admin` 可删除全部短链；`member` 仅可删除本人创建的短链，越权操作返回 403 Forbidden。
* **语义**: 软删除；历史访问明细保留，管理端默认不可见，同域名下原 Slug 立即释放。

### 5.7 封禁或解封短链
* **路径**: `PATCH /api/v1/links/{id}/ban`
* **权限规则**: 仅 Owner/Admin。
* **请求体**: `{ "isBanned": true, "reason": "命中安全风险规则" }`
* **语义**: 封禁优先级高于用户启停和过期状态；封禁时必须记录操作者、原因和 UTC 时间。

## 6. 深度数据分析与统计 (Analytics)

### 6.1 工作台概览
* **路径**: `GET /api/v1/analytics/overview`
* **响应 `data`**:
```json
{
  "totalLinks": 28,
  "totalPv": 19574,
  "totalUv": 11740,
  "activeDomains": 2,
  "pvGrowthRate": 15.8,
  "uvGrowthRate": 9.4
}
```

### 6.2 全局概览统计指标
* **路径**: `GET /api/v1/analytics/summary`
* **Query 参数**: 可选 `linkId`；当前前端不向该接口传 `range`，因此返回当前工作空间/指定短链的全周期汇总。
* **响应 `data`**:
```json
{
  "totalClicks": 19574,
  "totalUniqueVisitors": 11740,
  "activeLinksCount": 28,
  "todayClicks": 1420,
  "clicksGrowthRate": 15.8
}
```

## 7. 开放平台 API 密钥 (API Keys)

本节是前端 Phase 7 的冻结实现契约。当前前端占位类型中的 `prefix`/`maskedKey` 尚无真实 HTTP 调用，不作为已验收行为；Phase 7 必须统一改用本节的 `keyPrefix`，避免要求数据库保存可泄露密钥尾段的信息。

## 8. 公网短链重定向引擎 (Public Redirect Engine)

### 8.1 短链跳转接口
* **路径**: `GET /{slug}`
* **业务逻辑说明**:
  1. 严格规范化请求 `Host`（移除允许的端口、转小写 ASCII/Punycode，并拒绝非法字符），先命中已注册域名，再结合 `slug` 在数据库中精确匹配短链记录（需绕过多租户过滤）。状态页 URL 必须使用数据库命中的规范化域名构造，禁止直接回显原始 Host；未知 Host 固定 302 至配置的规范平台 404 URL。
  2. 校验 `isBanned`：若已封禁，返回 302 至 `https://{Host}/banned`。
  3. 校验 `isEnabled`：若暂停，返回 302 至 `https://{Host}/suspended`。
  4. 校验 `expiresAt`：若失效，返回 302 至 `https://{Host}/expired`。
  5. **密码保护短链流转**：
     * 若短链设置了密码，检查请求头中是否携带已放行的 Cookie：`art_pwd_ticket_{slug}`。
     * 若 Cookie 缺失或验签失败，**立即返回 302 重定向至前端 SPA 密码解锁页面**：`Location: https://{Host}/unlock/{slug}`。
     * 若 Cookie 验证通过，放行执行跳转。
  6. **非阻塞日志采集**：将访问事件（IP、User-Agent、Referer、访问时间、机器人和 UTM 快照）投递至 `System.Threading.Channels`，不阻塞跳转响应。
  7. **302 临时重定向**：仅返回 **HTTP 302 Found**，严禁 301；`Location` 为完整原始 URL。

### 8.2 密码保护短链解锁接口
* **路径**: `POST /api/v1/links/{slug}/unlock`
* **描述**: 公共接口，不要求 JWT 或 `X-Workspace-Id`；按请求 Host+Slug 唯一定位。校验通过后下发临时放行 Cookie，并返回目标长链接。
* **Host 安全**: 仅接受能命中 `link_domain` 的规范化 Host；未知/非法 Host 返回 HTTP 404 统一错误体，不得把原始 Host 写入票据或响应 URL。
* **请求体**:
```json
{
  "password": "访客输入的访问密码"
}
```
* **响应 `data`**:
```json
{
  "originalUrl": "https://dotnet.microsoft.com/download/dotnet/10.0",
  "ticket": "art_ticket_8f3a9e2c4d1b7a0f"
}
```
* **Response Headers (凭证 Cookie 写入)**:
  * `Set-Cookie: art_pwd_ticket_{slug}=<ticket>; Path=/; Max-Age=1800; HttpOnly; SameSite=Lax`
  * Production 环境追加 `Secure`；票据绑定规范化 Host、Slug 与到期时间并使用固定时间比较验签。
  * 说明：`ticket` 采用独立密钥签发的 HMAC-SHA256 Base64Url 票据，有效时长为 1800 秒（30分钟）。访客后续在有效期内直接访问 `GET /{slug}`，重定向引擎将直接放行，无需重复输入密码；响应必须设置 `Cache-Control: no-store`。
* **业务异常响应**:
  * 密码错误：`{ "code": 403, "success": false, "message": "访问密码错误，请核对后重试", "data": null }`
  * 链接不存在或已停用：`{ "code": 404, "success": false, "message": "短链不存在或已停止服务", "data": null }`
  * 解锁尝试触发限流：HTTP 429，响应体 `code` 同为 429。
