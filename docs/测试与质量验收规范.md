# 测试与质量验收规范 (Testing & Quality Assurance Guidelines)

本文档定义 **Arturia.ShortLink** 项目的前后端质量基准、人机协同大阶段走查、冒烟与集成测试、边界异常测试及代码发布门禁。
作为 **Agent 与人类开发者在大阶段验收时的共同裁决标准**，确保前端零白屏与零类型错误，后端具备可验证的租户隔离、数据完整性、安全性和异常韧性。

## 1. 质量目标与核心铁律

1. **零白屏与零未捕获异常 (Zero Uncaught Errors)**：
   * 任何页面加载、路由切换、表单提交或图表渲染过程中，浏览器开发者控制台（Console）严禁出现红色未捕获异常（`Uncaught Error` / `Uncaught Promise Rejection`）。
2. **零类型隐患 (Strict Type Safety)**：
   * `tsc --noEmit` 编译检查必须 **0 报错、0 警告**，严禁使用 `any` 逃避类型检查。
3. **高保真 Mock 闭环 (100% Mock Data Integrity)**：
   * 在 Mock 驱动模式下，增删改查必须在本地内存与持久化存储中形成真实闭环（例如：创建短链后列表立即出现、修改别名后生效、切换工作空间数据立即联动刷新）。
4. **全端响应式无水平溢出 (No Horizontal Scroll)**：
   * 在移动端（375px~430px）及桌面端（1024px~1920px）的视口下，页面整体不得出现任何非预期的横向滚动条。
5. **后端构建零警告与测试零跳过**：
   * Release 构建必须 0 警告、0 错误；规定的单元/集成测试必须 0 失败、0 取消、0 跳过。
6. **真实 MySQL 语义验证**：
   * EF Core 映射、生成列、索引、外键、排序规则和租户隔离测试必须使用独立的 `mysql:8.0.46` Testcontainer，禁止以 SQLite/InMemory 替代。
7. **凭据与隐私安全**：
   * Git Diff、日志和测试结果中不得出现真实数据库密码、JWT、Cookie、API Key 明文或短链密码；测试凭据只能使用文档声明的演示值。

| :--- | :--- | :--- |

| **阶段二：用户认证与租户空间** | 1. 登录与注册表单校验<br>2. 顶部工作空间下拉切换<br>3. 成员列表与邀请弹窗 | 输入非法邮箱即时提示；切换工作空间后当前 Header 租户即刻变化，成员列表正常增删。 |
| **阶段三：短链核心管理** | 1. 顶部快捷短链生成栏<br>2. 短链表格列表与搜索过滤<br>3. 启停开关与一键复制<br>4. CSV 数据导出 | 粘贴 URL 点击缩短立即生成 6 位短码；复制按钮出现 Tooltip 反馈；Switch 开关平滑翻转；导出 CSV 文件格式完整无乱码。 |

### 2.1 后端 Phase 1～5 验收矩阵

| 阶段 | 自动化与人工验收重点 | 通过标准 |
| :--- | :--- | :--- |
| **Phase 1：工程与数据底座** | SDK/版本一致性、NuGet 锁文件、EF 迁移、表/列/索引/生成列、种子幂等、健康检查与 Scalar | `.NET 10.0.303`；MySQL `8.0.46`；locked restore；Release 0 警告；跨租户与无租户查询默认拒绝；Scalar 可调用 version/health |

## 3. 边界输入与异常健壮性测试标准

业务表单与输入框必须通过以下极端与异常用例测试：

### 3.1 短链生成与目标 URL 校验
1. **非法伪协议测试**：输入 `javascript:alert(1)`、`data:text/html,...`，表单必须立即拦截并标红报错。
2. **防自环递归测试**：输入当前平台域名 `https://art.link/test`，前端必须明确提示“禁止将平台自身域名作为目标长链接”。
3. **超长 URL 健壮性**：输入 2048 字符的超长 URL，表格列表展示必须自动省略截断（`truncate`），悬浮展示完整 Tooltip，容器不得被撑破变形。
4. **短码别名字符集校验**：输入包含中文或特殊字符（如 `@#$%^&*`），表单必须提示“仅允许英文字母、数字、短横线及下划线”。

### 3.2 密码与时限边界
1. **密码输错测试**：在密码保护卡片中输入错误口令，卡片必须呈现微震动/晃动交互，给出“密码错误”明确提示，严禁静默失效。
2. **过期时间边界**：选择过去的日期时间，时间选择器必须自动校验并提示“失效时间必须晚于当前时间”。

## 5. 质量准入与自动化审查门禁 (CI/Quality Gates)

在大阶段人工审阅前，以及用户批准后、提交 PR 前，必须重新执行对应自动化门禁。审阅后发生任何代码或规范调整，相关门禁必须全量重跑。

### 5.1 前端门禁

```bash
# 门禁 1：TypeScript 强类型与无未使用变量编译检查
npm run build (内部包含 tsc -b)

# 门禁 2：代码规范与静态分析检查
npm run lint

# 门禁 3：生产打包体积与资产完整性核查
# 检查 dist/ 输出产物无缺失资源，单 chunk 压缩后体积小于 500KB
```

### 5.2 后端门禁

```powershell
dotnet --version
dotnet tool restore
dotnet tool run dotnet-ef --version
dotnet restore backend/Arturia.ShortLink.sln --locked-mode
dotnet build backend/Arturia.ShortLink.sln -c Release --no-restore
dotnet test backend/Arturia.ShortLink.sln -c Release --no-build
dotnet format backend/Arturia.ShortLink.sln --verify-no-changes
```

* `dotnet --version` 必须与 `global.json` 固定的稳定版 SDK 一致；迁移必须使用仓库工具清单锁定的 `dotnet-ef 9.0.20`，禁止调用不匹配的全局工具。
* 所有工程必须提交 `packages.lock.json`；普通 restore 仅允许 Phase 1 首次生成锁文件，门禁和 CI 必须使用 `--locked-mode`。
* 集成测试每次创建独立 MySQL 8.0.46 容器、数据库和随机端口，结束后销毁，不复用本机 `Arturia_Dev` 或其他容器。
* `/health/ready` 必须实际验证数据库可连接且迁移已应用；仅进程存活不能通过就绪门禁。
* Testcontainer、开发 Compose、迁移连接与 API 时间响应必须验证 UTC；不得依赖测试宿主的 Asia/Shanghai 本地时区。
* HTTP 测试必须同时断言状态码和统一 `ApiResponse`：业务失败不得用 HTTP 200 伪装。
* PR 前执行密钥扫描与 `git diff --check`；任一真实凭据命中立即阻断。

### 5.3 契约冻结专项门禁

* 已验收前端源码中的 28 个 Method/Path 组合必须全部出现在《接口契约规范》的调用矩阵并映射到后端 Phase。
* `docs/数据库设计.sql` 必须能在全新 MySQL 8.0.46 实例连续执行两次；验证系统域名共享、Host+Slug 冲突、自定义域名同 Slug、软删除释放和唯一主域名约束。
* 所有被修改的 `docs/` 文件必须同步追加文首修订流水；Diff 不得包含空白错误或真实凭据。
