# Arturia.ShortLink - 前端功能开发 TODO 清单 (Agent 唯一执行基准)

> ### 🛑 铁律与协作边界 (Strict Boundaries)
> 1. **专职边界 (Frontend Only)**：
>    * **Agent（我）职责**：**100% 仅负责前端工程**。包括所有 React 页面、开源组件组装、交互逻辑、状态管理、图表联动与高保真 Mock 数据服务。**严禁编写任何后端代码，严禁越界**。
>    * **用户（你）职责**：负责手动编写 **.NET 10 + C# WebAPI + MySQL 后端**。
> 2. **Mock 驱动一切 (Mock-Driven Development)**：
>    * 前端所有接口交互（登录鉴权、短链增删改查、域名验证、统计图表聚合、API 密钥生成等）**全部由前端本地 Mock 服务引擎提供响应**。
>    * 保证前端脱离后端即可 100% 独立流畅运行，提供真实、高保真的操作反馈与数据联动。
> 3. **人机协同大阶段验收、PR 与自动合并闭环 (Human-in-the-Loop Workflow)**：
>    * 严格以**大阶段（Phase）**为进度推进单元。
>    * **大阶段启动前基线对齐与切支**：开发启动前检查工作区纯净，`git checkout main && git pull --rebase origin main` 同步远端最新基线；随后切出独立特性分支 `feat/phase-X-<name>`（若遇冲突自动 `git rebase --abort` 并报警）。
>    * **每完成一个大阶段全部开发后，Agent 必须主动通过指令在用户默认浏览器中打开页面供人工审阅**。
>    * **用户明确确认同意后，Agent 自动提交推送特性分支、通过 `gh pr create` 发起 Pull Request、再调用 `gh pr merge --squash --delete-branch` 完成自动合并并切回 main 同步，并在本清单中勾选 `[x]`，随后立即原地暂停，等待下一阶段指令**。
> 4. **唯一执行准绳 (Single Source of Truth)**：
>    * Agent 后续开发必须**严格按照本清单项逐一推进**，严禁跑偏、严禁漏项、严禁擅自新增未经确认的功能。
>    * 若后续有任何需求变更或新增功能，**必须先同步更新《需求规格说明书.md》与本清单**，得到明确确认后方可落地。
> 5. **状态标记约定**：
>    * `[ ]`：待开始 (Pending)
>    * `[-]`：进行中 (In Progress)
>    * `[x]`：已完成并通过验收 (Completed)
