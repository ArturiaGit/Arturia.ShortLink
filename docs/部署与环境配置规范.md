## 1. 环境变量配置规范 (.env)

项目采用 Vite 标准环境变量机制，通过在变量名前附加 `VITE_` 暴露给前端客户端代码。

### 1.1 环境变量文件矩阵

| 文件名 | 适用运行模式 | Git 状态 | 职责说明 |
| :--- | :--- | :--- | :--- |
| **`.env`** | 所有模式全局默认 | 纳入版本库 | 声明基础通用变量（应用名称、默认域名） |
| **`.env.development`** | 本地开发 (`npm run dev`) | 纳入版本库 | 默认启用本地 Mock 服务引擎 (`VITE_USE_MOCK=true`) |
| **`.env.production`** | 生产构建 (`npm run build`)| 纳入版本库 | 关闭 Mock，直连真实后端 API 相对路径 |
| **`.env.local`** | 本地个人覆盖配置 | **.gitignore 忽略** | 个人私有调试配置，严禁提交到远端仓库 |

### 1.2 核心变量清单

```ini
# ==============================================================================
# Arturia.ShortLink - 环境变量配置范本
# ==============================================================================

# 应用对外品牌名称
VITE_APP_TITLE="Arturia ShortLink"

# 是否启用前端本地 Mock 模拟数据引擎 (true / false)
# 本地研发阶段设为 true 即可免后端全功能运行；联调与生产设为 false
VITE_USE_MOCK=true

# 后端 RESTful API 基础请求路径
# 本地开发对接后端: http://localhost:5000
# 生产环境经 Nginx 反向代理: /api/v1
VITE_API_BASE_URL="/api/v1"

# 平台系统共享默认短链域名
VITE_DEFAULT_DOMAIN="art.link"

# 全局版本号注入 (由构建流水线或 package.json 注入)
VITE_APP_VERSION="0.1.0"
```

## 2. Vite 生产构建与体积优化

为保障生产环境极速首屏加载体验，前端在 `vite.config.ts` 中确立以下构建与分包优化策略：

### 2.1 依赖代码分割 (Chunk Splitting)
通过 Rollup 的 `manualChunks` 将体积较大的第三方通用库拆分为独立 Chunk，利用浏览器缓存机制减少重复拉取：

```typescript
// vite.config.ts 生产构建优化配置参考
build: {
  target: 'es2022',
  minify: 'esbuild',
  chunkSizeWarningLimit: 600,
  rollupOptions: {
    output: {
      manualChunks: {
        'vendor-react': ['react', 'react-dom'],
        'vendor-charts': ['recharts'],
        'vendor-icons': ['lucide-react'],
      },
    },
  },
}
```

### 2.2 静态资产缓存策略
* 编译输出带有 Hash 指纹的文件（`assets/[name]-[hash].js`、`.css`）配置强缓存：`max-age=31536000, immutable`。
* `index.html` 严禁强缓存，必须始终配置协商缓存：`no-cache`。

## 3. Nginx 生产反向代理配置范本

在生产服务器中，推荐使用 Nginx 统一承载前端静态 SPA 页面托管、后端 .NET 10 API 反代以及公网短链 302 跳转路由：

```nginx
# ==============================================================================
# Arturia.ShortLink - Nginx 生产服务器统一配置
# ==============================================================================

server {
    listen 80;
    server_name art.link *.art.link;

    # 启用 Gzip 压缩，大幅降低传输带宽
    gzip on;
    gzip_min_length 1k;
    gzip_comp_level 6;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml application/xml+rss text/javascript image/svg+xml;
    gzip_vary on;

    # 1. 前端编译产物静态托管根目录
    root /usr/share/nginx/html;
    index index.html;

    # 2. 静态带 Hash 指纹的资产强缓存 1 年
    location ~* \.(?:css|js|woff2?|svg|png|jpg|ico)$ {
        expires 1y;
        add_header Cache-Control "public, max-age=31536000, immutable";
        access_log off;
    }

    # 3. 后端 RESTful API 反向代理 (转发至 .NET 10 Kestrel 5000 端口)
    location /api/ {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection keep-alive;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
        proxy_read_timeout 60s;
    }

    # 4. 前端 SPA 单页面路由回退支持 (杜绝刷新 404)
    # 控制台路由 (如 /links, /analytics, /domains) 回退至 index.html
    location / {
        try_files $uri $uri/ @shortlink_redirect;
    }

    # 5. 若非前端静态文件或路由，则转发至 .NET 10 执行公网短链 302 重定向
    location @shortlink_redirect {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 4. Docker 容器化构建与编排方案

### 4.1 前端 Multi-Stage 多阶段 Dockerfile

```dockerfile
# ------------------------------------------------------------------------------
# 阶段 1：依赖安装与构建打包 (Build Stage)
# ------------------------------------------------------------------------------
FROM node:24-alpine AS builder
WORKDIR /app

# 利用 Docker 缓存层
COPY package*.json ./
RUN npm ci

COPY . .
# 执行 TypeScript 编译与 Vite 生产打包
RUN npm run build

# ------------------------------------------------------------------------------
# 阶段 2：轻量生产运行镜像 (Serve Stage - 镜像体积 < 25MB)
# ------------------------------------------------------------------------------
FROM nginx:alpine-slim
WORKDIR /usr/share/nginx/html

# 清理默认页面并复制编译产物
RUN rm -rf ./*
COPY --from=builder /app/dist .
COPY nginx.conf /etc/nginx/conf.d/default.conf

EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

### 4.2 全栈 Docker Compose 编排范例 (`docker-compose.yml`)

```yaml
version: '3.8'

services:
  # 前端 Web 容器 (Nginx 驱动)
  frontend:
    build:
      context: ./frontend
      dockerfile: Dockerfile
    ports:
      - "80:80"
    depends_on:
      - backend
    restart: always

  # 后端 .NET 10 WebAPI 容器
  backend:
    image: arturia-shortlink-api:latest
    environment:
      - ASPNETCORE_ENVIRONMENT=Production
      - ConnectionStrings__DefaultConnection=Server=mysql;Database=arturia_shortlink;User=root;Password=YourSecurePassword123!;
      - Redis__ConnectionString=redis:6379
    depends_on:
      - mysql
      - redis
    restart: always

  # MySQL 8.x 关系型数据库
  mysql:
    image: mysql:8.0
    command: --default-authentication-plugin=mysql_native_password --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci
    environment:
      MYSQL_ROOT_PASSWORD: YourSecurePassword123!
      MYSQL_DATABASE: arturia_shortlink
    volumes:
      - mysql_data:/var/lib/mysql
      - ./docs/数据库设计.sql:/docker-entrypoint-initdb.d/init.sql
    restart: always

  # Redis 缓存集群
  redis:
    image: redis:7-alpine
    volumes:
      - redis_data:/data
    restart: always

volumes:
  mysql_data:
  redis_data:
```
